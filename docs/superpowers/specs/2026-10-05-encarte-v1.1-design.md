# Encarté 1.1.0, sub-project A "At checkout" — Design Spec

- **Date:** 2026-10-05
- **Status:** Draft, pending review
- **Parent spec:** `2026-10-03-encarte-design.md`

## 1. Context and goals

v1.0.0 is tagged and in Play review. Release 1.1.0 is built in three sub-projects, each with its own spec, plan and reviews. `v1.1.0` is tagged only once all three are done and the finalization step (§6) has run:

- **A — "At checkout" and fixes:** this spec.
- **B — Organisation:** groups, a home-screen widget and app shortcuts. Separate spec.
- **C — Migration:** import from FidMe, and import of pkpass and PDF files. Separate spec.

A comparison with Catima, done on 2026-10-05, picked three features for v1.1, all about using cards at checkout and keeping the list tidy:

1. **Block contactless payment while a card is shown.** Holding the phone to a terminal to show a loyalty card can trigger the phone's NFC payment. This is a setting, on by default.
2. **Card expiry date.** It is useful for vouchers, gift cards and annual membership cards. Cards show a badge and can be sorted by expiry. "Valid from" and "balance" were deliberately left out, because the app has no way to keep a balance true.
3. **Archive.** Archived cards live in a collapsed section at the bottom of the list.

Decisions taken with the user (2026-10-05):
- NFC blocking is a setting, on by default.
- Archived cards go in a collapsed "Archived (n)" section at the bottom, and search finds them last.
- Expiry shows badges, plus an "Expiry" sort. Nothing is archived automatically.

Success criteria:

1. Upgrading from 1.0.0 keeps every card and photo. New fields default to "no expiry" and "not archived", and a migration test proves it.
2. While a card is displayed with the setting on, a contactless terminal cannot trigger the phone's payment. This is checked manually on a real terminal.
3. An Encarté → Catima → Encarté round trip keeps the expiry date and the archived state.
4. The app still requests no network permission (`verifyNoNetworkPermission` stays green).

## 2. Data

**`Card` gains two fields:**
- `expiresOn: LocalDate?`, default `null`, stored as epoch day (`Long`) through a new Room converter.
- `isArchived: Boolean`, default `false`.

**Expiry status** is pure logic with an injectable "today":
- **None:** no date.
- **Soon(daysLeft):** today ≤ expiresOn ≤ today + 30 days. `daysLeft = expiresOn − today`, and 0 means "expires today".
- **Expired:** expiresOn < today. A card is valid through the whole day of its expiry date.

**Sort orders:** `SortOrder` gains `EXPIRY`. Cards with a date come first, by ascending date (expired cards at the top), then cards without a date, by name with the existing locale-aware collator. Favorites, the other active cards and archived cards are sorted with the selected order inside each section.

**Preferences (DataStore):** `nfcBlockEnabled: Boolean`, default `true`.

## 3. Database migration 1 → 2

- `EncarteDatabase` moves to `version = 2`, with a **Room auto-migration from 1 to 2**. It only adds two columns:
  - `expiresOn INTEGER NULL`;
  - `isArchived INTEGER NOT NULL DEFAULT 0`.

  Existing rows are not rewritten. If Room 3's auto-migration cannot express this, a manual `Migration(1, 2)` with the two `ALTER TABLE … ADD COLUMN` statements does the same.
- The exported schema `app/schemas/…/2.json` is committed next to `1.json`.
- **Migration test.** The existing `MigrationTestHelper` setup, with schemas exposed to debug unit tests, does the following:
  1. creates a v1 database;
  2. inserts cards with all v1 columns filled;
  3. migrates;
  4. checks every v1 value unchanged, `expiresOn` null and `isArchived` 0;
  5. checks the DAO reads the rows.

## 4. Catima import and export

**Import:**
- Catima's `expiry` (epoch milliseconds) becomes `expiresOn`, converted with the device time zone (`Instant.ofEpochMilli(ms).atZone(zone).toLocalDate()`). It is **no longer appended to the note**.
- Catima's `archive` becomes `isArchived`.
- `validfrom` and `balance` keep today's behaviour and are appended to the note.

**Export:**
- `expiresOn` becomes `expiry`, as epoch milliseconds at the start of that day in the device time zone.
- `isArchived` becomes `archive = 1`.

Notes written by v1.0 imports ("Expire le …") are not parsed back into the field.

**Tests:**
- mapping in both directions;
- the round trip keeps both fields;
- a Catima fixture with an expiry date and an archived card.

## 5. Screens

### 5.1 Card list
- **Sections, in order:** Favorites, All cards, and a collapsible header "Archivées (n)" / "Archived (n)", collapsed by default.
  - The collapsed state lives in `rememberSaveable`, so it survives rotation but is not persisted.
  - Archived cards appear only in the archived section, even if they are favorites.
  - The header is shown only when n > 0.
- **Search** covers archived cards too. Active matches come first, then the archived section, expanded automatically while a query is entered.
- **Tile badge:** a small pill in the tile's top end corner, with its own opaque background, so it stays readable on any tile color or photo.
  - **Soon:** "Expire dans 5 j" / "Expires in 5 d", or "Expire aujourd'hui" / "Expires today" at 0 days. Background `#F2A93B`, text `#1D2440`.
  - **Expired:** "Expirée" / "Expired". Background `#D32F2F`, text `#FFFFFF`.
  - Its text is part of the tile's accessibility description.
  - A 1 dp outline in the badge's text color keeps the pill visible on a tile of the same color (amber badge on an amber card, red on red). Decided with the user after the emulator review (2026-10-05).
- **Sort menu:** new entry "Échéance" / "Expiry date".

### 5.2 Card display
- **Expiry line** below the card number:
  - "Expire le 12 mars 2027" / "Expires on 12 March 2027", in the localized medium date format;
  - once past: "Expirée depuis le …" / "Expired on …", in the error color.
- **Archive action** in the top bar's overflow menu (Material Symbols `more_vert`, content description "Plus d'options" / "More options"), together with Delete. Favorite and Edit stay as icons. With four icons the store name broke mid-word ("Fromager/ie"), so the user chose the menu after the emulator review (2026-10-05).
  - The menu items show the Material Symbols `archive` / `unarchive` and `delete` icons, added as vector drawables like the existing icons.
  - Labels: "Archiver" / "Archive" and "Désarchiver" / "Unarchive", then "Supprimer" / "Delete".
  - The title takes at most two lines, then ends with "…".
  - **Archiving** returns to the list and shows a snackbar "Carte archivée" / "Card archived", with an "Annuler" / "Undo" action that unarchives it.
  - **Unarchiving** stays on the screen.
- **NFC blocking:**
  - While the screen is shown and resumed, if `nfcBlockEnabled` is true and an `NfcAdapter` exists and is enabled, the activity enters reader mode: `NfcAdapter.enableReaderMode` with flags for all tag technologies, `FLAG_READER_SKIP_NDEF_CHECK` and `FLAG_READER_NO_PLATFORM_SOUNDS`, and a callback that ignores tags. Reader mode stops card emulation for the foreground activity, so a terminal cannot reach the phone's payment app.
  - It is disabled when the screen pauses or leaves composition.
  - The calls go through a small `ContactlessGuard` interface with a real implementation and a fake for tests.
  - Manifest: `<uses-permission android:name="android.permission.NFC"/>` and `<uses-feature android:name="android.hardware.nfc" android:required="false"/>`.

### 5.3 Card edit
- **Field:** "Date d'expiration (facultatif)" / "Expiry date (optional)". It opens a Material 3 `DatePickerDialog`.
- **Clear button:** "Effacer la date" / "Clear date".
- The date shows in the localized medium format.
- **Archived state:** editing an archived card keeps it archived. The edit screen has no archive switch.

### 5.4 Settings
- A new section "En caisse" / "At checkout", above Backup, shown only if the device has `PackageManager.FEATURE_NFC`. It holds:
  - a switch titled "Bloquer le paiement sans contact" / "Block contactless payment";
  - a summary: "Pendant l'affichage d'une carte, un terminal ne peut pas déclencher le paiement de votre téléphone." / "While a card is shown, a terminal can't trigger your phone's payment."

## 7. Fixes bundled in sub-project A

The user chose these from the known follow-ups (2026-10-05).

1. **Scanner buttons at 360 dp.** "Depuis une image" wraps onto two lines on 360 dp screens, and the two side-by-side buttons end up with different heights. Fix: the row uses `IntrinsicSize.Min` height and each button `fillMaxHeight()`, so both buttons are always the same height.
2. **Cancel in the export dialog.** Today the export password dialog only offers "Exporter" and "Exporter sans mot de passe", so Back is the only way out.
   - Add "Annuler" / "Cancel", which closes the dialog without exporting.
   - The three buttons sit in an end-aligned `FlowRow`, so they wrap onto two lines on narrow screens instead of overflowing.
   - Order, from the end: Exporter, Sans mot de passe, Annuler.
3. **2D codes in landscape.** On the card display, a 2D code fills the width (up to 640 dp) and stays square, so in landscape it is taller than the screen and you must scroll at checkout.
   - Fix: the barcode area's height is capped to what fits in the viewport below the top bar, leaving room for the card number line.
   - A 2D code stays square and centered at that size.
   - Portrait layouts are unchanged.
   - **Test:** a Compose test at `w891dp-h411dp-land` checks that the barcode's bounds lie within the window.
4. **Dialogs, menus and the lock.** When the app relocks, the lock screen covers the activity's content, but dialogs and popup menus are separate windows drawn above it.
   - **Today:** each one must remember to hide itself when `LocalContentCovered` is true.
   - **Fix:** `core/ui/CoverableWindows.kt` provides `EncarteAlertDialog`, `EncarteDialog`, `EncarteDropdownMenu` and `EncarteDatePickerDialog`, which wrap the Material and Compose components and render nothing while content is covered. Every existing dialog and menu, and v1.1's date picker, uses them.
   - **Guard test:** a JVM unit test scans `app/src/main/java` and fails if any file other than `CoverableWindows.kt` calls `AlertDialog(`, `Dialog(`, `DropdownMenu(`, `DatePickerDialog(`, `ModalBottomSheet(` or `Popup(` directly. That way a future dialog cannot forget the protection.
   - **Behaviour test:** with content covered, an `EncarteAlertDialog` shows nothing.

The user also chose to retake the store screenshots. That happens in the finalization step (§6), so the shots show all of 1.1.0.

## 8. Out of scope

- "Valid from" and balance fields.
- Expiry notifications: they would need the notification permission, for little value.
- Automatic archiving.
- Re-blocking contactless payment when NFC is switched on while a card is already shown: the block applies from the next time the screen resumes. The user chose to leave it (2026-10-05).
- Parsing old "Expire le …" notes.
- The startup orphan-photo sweep race. The user did not select it for v1.1.
- Groups, widget and app shortcuts: sub-project B.
- FidMe, pkpass and PDF import: sub-project C.
- The version bump, changelogs, store descriptions and screenshots: the finalization step (§6).
